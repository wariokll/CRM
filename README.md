# БАЗИС CRM

Готовая CRM для приёма и обработки заявок сервисного отдела. Интерфейс и API доступны из одного процесса по адресу `http://localhost:3001`.

## Уже развёрнуто на этой машине

- React/Vite frontend собран в `dist`;
- Express/TypeScript backend собран в `backend/dist`;
- отдельная MariaDB 11.7 (совместимый с Prisma `mysql` сервер) работает на `127.0.0.1:3307`;
- схема применена миграцией Prisma, справочник типов заполнен;
- база слушает только localhost и не конфликтует с существующими службами на 3305/3306;
- runtime-секреты находятся в исключённом из Git файле `backend/.env`;
- данные БД находятся в исключённом из Git каталоге `backend/.mysql-data`.

### Учётные записи

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin@bazis.ru` | `admin` |
| Демонстрационный клиент | `user@bazis.ru` | `user` |

Пароли предназначены для первого локального входа. Перед публикацией системы смените их и значения `JWT_*`, `ENCRYPTION_KEY`, а также пароли БД.

## Запуск и остановка

Из PowerShell в корне проекта:

```powershell
npm start
```

Скрипт запускает изолированную БД, backend и открывает браузер. Остановка:

```powershell
npm stop
```

Логи находятся в `backend/.logs`. Backend после запуска работает по адресу `http://localhost:3001`, проверка состояния — `http://localhost:3001/api/health`.

## Временный доступ для демонстрации

Когда CRM запущена, выполните в отдельном окне PowerShell:

```powershell
.\start-demo-tunnel.ps1
```

Скрипт выведет временную публичную ссылку вида `https://....lhr.life`. Она работает, пока открыто окно туннеля и запущена CRM. Для остановки нажмите `Ctrl+C` или выполните `.\stop-demo-tunnel.ps1`. Бесплатный адрес может измениться при следующем запуске; используйте этот режим только для краткой демонстрации, а не для постоянной публикации.

## Разработка

Требуется Node.js 20+ и запущенная локальная БД на порту 3307.

```powershell
# терминал 1
cd backend
npm run dev

# терминал 2, из корня
npm run dev
```

Vite проксирует `/api` на `http://localhost:3001`. Production-сборка и тесты:

```powershell
npm run build
cd backend
npm run build
npm test
```

Новые миграции создаются через `npx prisma migrate dev --name <имя>` в `backend`; на сервере применяются командой `npm run prisma:deploy`.

## Реализовано

- регистрация клиента, JWT access/refresh, bcrypt, rate-limit входа;
- статусы регистрации `pending / active / rejected / blocked`;
- ручное создание и блокировка клиентов администратором;
- несколько торговых точек, отдельная модерация новых точек;
- зашифрованные AES-256-GCM доступы AnyDesk, ОФД и налоговой;
- срочные и плановые заявки, фильтры, поиск, комментарии и контролируемые переходы статусов;
- календарь с видами месяц/неделя/день;
- справочник типов заявок с soft delete;
- административная статистика и адаптивный интерфейс;
- polling данных раз в 45 секунд;
- таблицы вложений и уведомлений заложены в схему для дальнейшего расширения.

## Резервное копирование

Создание дампа (пароль будет запрошен интерактивно):

```powershell
& 'C:\Program Files\MariaDB 11.7\bin\mariadb-dump.exe' `
  --host=127.0.0.1 --port=3307 --user=crm_user --password `
  --single-transaction --result-file=D:\Backups\servio_crm.sql servio_crm
```

Добавьте эту команду в Планировщик заданий Windows и храните копии на отдельном диске. Периодически проверяйте восстановление дампа на тестовой БД.

## Публикация на Windows-сервере

1. Смените все секреты и пароли в `backend/.env`.
2. Установите HTTPS reverse proxy перед портом 3001: IIS + ARR/URL Rewrite либо nginx. Включите `COOKIE_SECURE=true` только после настройки HTTPS.
3. Зарегистрируйте `backend/dist/server.js` как службу через NSSM либо PM2 и настройте автоматический запуск базы. Локальные `start-crm.ps1` / `stop-crm.ps1` предназначены для текущей машины без административных прав.
4. Разрешайте доступ к 3001 только reverse proxy; порт БД 3307 должен оставаться привязанным к `127.0.0.1`.

## Ограничения браузера

AnyDesk открывается ссылкой `anydesk:<ID>`, а пароль копируется отдельно: браузер не может безопасно подставить его в нативное окно AnyDesk. Логины и пароли ОФД/ФНС также копируются вручную из CRM; автоматическое заполнение сторонних сайтов не используется.
