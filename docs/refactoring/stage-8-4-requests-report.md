# Этап 8.4 — request-модуль

## 1. Что сделано

Разделён request-модуль: `request.routes.ts` содержит регистрацию маршрутов и middleware; тонкие HTTP-контроллеры находятся в `request.controller.ts`; запросы к БД, проверки бизнес-правил, транзакции и побочные уведомления вынесены в `request.service.ts`. Существующие схемы в `request.contracts.ts`, policy, include и отчёты сохранены.

Размеры файлов:

| Файл                    |           До |       После |
| ----------------------- | -----------: | ----------: |
| `request.routes.ts`     | 26 453 байта |  1 355 байт |
| `request.controller.ts` | отсутствовал |  4 766 байт |
| `request.service.ts`    | отсутствовал | 24 390 байт |

## 2. Проверка `npm.cmd run verify`

Полный прогон прошёл: проверка кодировки, TypeScript, ESLint, Prettier; frontend — 2 файла/4 теста; backend — 37 файлов/116 тестов. Backend coverage: statements 84.29%, branches 66.48%, functions 84.81%, lines 85.53%. Frontend/backend production builds, SPA fallback и Playwright 11/11 прошли. Проверка Prisma миграций не обнаружила расхождений.

## 3. Тесты

Новые тесты не добавлялись. Существующие request characterization и контрактные тесты прошли в полном backend прогоне. Их проверка на baseline не требуется для этого рефакторинга.

## 4. Изменение существующих тестов

Нет.

## 5. Отклонения

Схема БД и миграции не менялись. Парсинг схемы для create/update/comment оставлен в сервисных операциях там, где перенос в middleware мог изменить порядок валидации относительно проверки доступа и существования заявки. Статусные исключения сервиса преобразуются контроллером в прежний HTTP-ответ.

## 6. Наблюдаемое поведение

API-контракты не менялись по намерению; точные HTTP-сценарии request suites прошли. Отдельных новых багов в ходе этого переноса не выявлено.

Не требуется для завершения этого подэтапа; обязательные сценарии прогнаны через API suites и Playwright.
