# Сверка ТЗ рефакторинга CRM: требования вне тестов

Дата сверки: 2026-11-26  
Основа: `ТЗ рефакторинг CRM.docx`, текущее состояние ветки `refactor/stage-8`.  
Область: архитектура, код, документация и развёртывание. Тесты, coverage и тестовые критерии в эту сверку не включены.

## Итог

Основные элементы целевой архитектуры добавлены: backend разделён на feature-модули, есть `createApp`, конфигурация валидируется Zod; frontend использует React Router, TanStack Query, Auth Context, URL для основных разделов и 404-страницу. Старые `backend/src/routes/` файлы отсутствуют, корневые `src/api.ts` и `src/types.ts` являются реэкспортами. Схема БД в рамках рефакторинга не менялась.

Полного соответствия ТЗ нет. Ниже перечислены незакрытые требования вне тестов и причины, указанные в имеющихся отчётах.

## Частично выполнено

- **Состояние и запросы в URL.** Разделы доступны по URL; фильтры, выбор доски, статья базы знаний, параметры отчёта, связанные сущности и открытые диалоги создания организации/сотрудника или редактирования доступа сериализуются в query string. Деталь заявки открывается по `/requests/:requestId`.
- **React Query.** Требования к `staleTime`, `refetchOnWindowFocus`, централизованным ключам, `useQuery` и feature mutation hooks реализованы. После успешных мутаций страницы сохраняют прежний callback обновления данных. Общие данные приложения продолжают опрашиваться каждые пять секунд в [useAppData.ts](../../src/features/layout/useAppData.ts); это наблюдаемое ранее поведение, поэтому само по себе изменение интервала могло бы нарушить требование сохранять семантику.
- **Точная целевая структура frontend.** Провайдеры устанавливаются в `main.tsx`; общие UI-компоненты остаются в `src/components/`, feature-код лежит непосредственно в папках фич без полного разделения на `api.ts`, `pages/` и `components/`. Поведение маршрутизации и загрузки страниц реализовано, но структура отличается от схемы из ТЗ.

## Выполненные пункты, подтверждённые кодом

- Backend: `createApp`, отдельный `server.ts`, Zod-проверка окружения, общий Prisma singleton, общий error handler и middleware; старые файлы `backend/src/routes/` удалены, маршруты находятся в feature-модулях.
- Frontend: `createBrowserRouter`, прямая адресация основных разделов, 404-страница, лениво загружаемые feature-страницы, auth/query providers и проверка доступных разделов.
- Корневые `src/api.ts` и `src/types.ts` служат реэкспортами. `shared-types/` подключён через tsconfig alias без workspaces и runtime-зависимости.
- В рамках рефакторинга не добавлялись миграции и не менялась схема БД.

## Границы этой сверки

Тесты, characterization-требования, Playwright, CI-тестирование и проценты coverage намеренно не оценивались. Этот документ фиксирует только кодовые, архитектурные, документационные и эксплуатационные пункты ТЗ вне тестов.
