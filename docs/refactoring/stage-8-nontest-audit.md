# Сверка ТЗ рефакторинга CRM: требования вне тестов

Дата актуализации: 2026-11-27. Основа: `ТЗ рефакторинг CRM.docx`, рабочая ветка `master`. Проверка сфокусирована на коде, архитектуре, API/БД, документации и локальном запуске; тесты учитываются только как регрессионное подтверждение.

## Итог

Основные функциональные этапы рефакторинга завершены. Backend использует модульные routes/controllers/services и фабрику `createApp(deps)`; frontend использует React Router, TanStack Query, URL state и feature hooks. Крупнейшие области, отмеченные в предыдущей сверке, дополнительно разделены по ответственности. Внешние API контракты, порядок наблюдаемых HTTP ответов и Prisma schema сохранены.

Полное буквальное совпадение со всеми структурными примерами ТЗ не достигнуто. Оставшиеся отклонения указаны ниже отдельно. Развертывание через Docker, Windows services и production/LAN намеренно исключены по прямому указанию пользователя.

## Оставшиеся отклонения и ограничения

| Требование ТЗ                                                                                   | Статус       | Причина / решение                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------------------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Docker, установка Windows services, production/LAN deployment                                   | Не выполнено | Пользователь прямо указал, что Docker не нужен и запускать следует без служб. Приложение запускается локально вручную.                                                                                                                                                                                                                                                                |
| Перенос request validation из сервисов в middleware                                             | Не выполнен  | Перестановка валидации относительно авторизации и проверки существования записи может поменять HTTP статус/тело. Валидация оставлена рядом с операциями для сохранения наблюдаемого API поведения.                                                                                                                                                                                    |
| Guards `RequireAuth` / `RequireRole`                                                            | Выполнено    | Оба компонента подключены к app shell. `RequireRole` использует прежний `buildNavigation` как единственный источник прав; `RequireAuth` показывает те же boot, login и inactive-account экраны.                                                                                                                                                                                       |
| Физическая структура frontend features                                                          | Выполнено    | TSX файлы разложены по `components/`, `pages/` и `hooks/`; feature-specific типы размещаются в `types/`, если они есть. API/query модули остаются в feature root, чтобы страницы и hooks могли импортировать их без лишнего barrel слоя. Root `api.ts` и `types.ts` являются только реэкспортами.                                                                                     |
| Ориентир размера файлов около 300 строк, функций около 50 строк, UI-компонентов около 200 строк | Частично     | В исходниках больше нет файлов свыше 300 строк; UI-компоненты укладываются примерно в 200 строк. Несколько backend service/controller composition factories и feature hooks длиннее 50 строк из-за замыканий над общей Prisma/React state областью; дальнейшее дробление требует выносить обязанности, а не только сокращать метрики. Текущие максимумы перечислены в инвентаризации. |

## Проверка после завершающих изменений

Последний полный `npm.cmd run verify` завершился успешно: проверка UTF-8; frontend/backend TypeScript; ESLint; Prettier; frontend 10/10; backend 116/116; production builds; SPA fallback smoke; Playwright 12/12. Prisma сообщила об отсутствии pending migrations и schema diff. Изменения в API и БД не вносились.

## Границы сверки

Не включены пункты, требующие Docker, установки служб или production/LAN окружения. Не менялись DB schema, миграции, endpoint payloads и порядок проверок, от которого зависят HTTP ответы.
