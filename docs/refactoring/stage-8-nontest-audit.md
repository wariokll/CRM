# Сверка ТЗ рефакторинга CRM: требования вне тестов

Дата актуализации: 2026-11-26. Основа: `ТЗ рефакторинг CRM.docx`, рабочая ветка `master`. Проверка сфокусирована на коде, архитектуре, API/БД, документации и локальном запуске; тесты учитываются только как регрессионное подтверждение.

## Итог

Основные функциональные этапы рефакторинга завершены. Backend использует модульные routes/controllers/services и фабрику `createApp(deps)`; frontend использует React Router, TanStack Query, URL state и feature hooks. Крупнейшие области, отмеченные в предыдущей сверке, дополнительно разделены по ответственности. Внешние API контракты, порядок наблюдаемых HTTP ответов и Prisma schema сохранены.

Полное буквальное совпадение со всеми структурными примерами ТЗ не достигнуто. Оставшиеся отклонения указаны ниже отдельно. Развертывание через Docker, Windows services и production/LAN намеренно исключены по прямому указанию пользователя.

## Выполнено в завершающих подэтапах

| Область                    | Результат                                                                                                                                                                                          |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Request backend            | Чтение, создание, обновление, policy, уведомления и подготовка целей разнесены по отдельным модулям. HTTP порядок проверок и payload сохранены.                                                    |
| Boards backend             | Основной сервис разделён на core, structure, cards и archive обязанности.                                                                                                                          |
| Boards frontend            | `BoardsPage` разделён на страницу, рабочее поле и диалоги; состояние страницы, действия и drag handler находятся в отдельных hooks/modules. URL selection и оптимистические перемещения сохранены. |
| Knowledge backend/frontend | Импорт отделён от основного сервиса. URL/query state, редактор, импорт и загрузка данных разделены между page/editor/import hooks и data helper.                                                   |
| Telegram bot               | Базовые операции, staff linking, выбор организации/точки и диспетчер событий разнесены на модули; общая сессия диалога сохранена.                                                                  |
| Stores UI/backend          | Карточка/форма доступа/toolbar и response mapper отделены от страницы/сервиса.                                                                                                                     |
| Кодировка и данные         | Изменённые тексты сохранены в UTF-8. Миграций и изменений Prisma schema нет.                                                                                                                       |

## Оставшиеся отклонения и ограничения

| Требование ТЗ                                                                                       | Статус       | Причина / решение                                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------------------------------------------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Docker, установка Windows services, production/LAN deployment                                       | Не выполнено | Пользователь прямо указал, что Docker не нужен и запускать следует без служб. Приложение запускается локально вручную.                                                                                                                                                                                            |
| Перенос request validation из сервисов в middleware                                                 | Не выполнен  | Перестановка валидации относительно авторизации и проверки существования записи может поменять HTTP статус/тело. Валидация оставлена рядом с операциями для сохранения наблюдаемого API поведения.                                                                                                                |
| Буквальное имя-компонент `RequireRole`                                                              | Не добавлено | Доступ реализован системой permissions и страницей отказа, покрывающей текущие роли/права. Отдельный компонент с дублирующей проверкой создавал бы второй источник правил.                                                                                                                                        |
| Точное физическое расположение каждой frontend feature по схеме `api.ts` / `pages/` / `components/` | Частично     | Функциональные границы уже организованы по feature-папкам. Массовые перемещения файлов без изменения контрактов не требуются для текущей архитектуры и создают шумный diff.                                                                                                                                       |
| Ориентир размера файлов около 300 строк, функций около 50 строк, UI-компонентов около 200 строк     | Частично     | Бывшие крупные hotspots разделены. В актуальной таблице инвентаризации остаются файлы примерно 200–294 строк; часть factory/hooks содержит длинные замыкания над общей state/dependency областью. Их дальнейшее дробление допускается только при сохранении понятных границ и поведения, без искусственных слоёв. |

## Проверка после завершающих изменений

Последний полный `npm.cmd run verify` завершился успешно: проверка UTF-8; frontend/backend TypeScript; ESLint; Prettier; frontend 10/10; backend 116/116; production builds; SPA fallback smoke; Playwright 12/12. Prisma сообщила об отсутствии pending migrations и schema diff. Изменения в API и БД не вносились.

## Границы сверки

Не включены пункты, требующие Docker, установки служб или production/LAN окружения. Не менялись DB schema, миграции, endpoint payloads и порядок проверок, от которого зависят HTTP ответы.
