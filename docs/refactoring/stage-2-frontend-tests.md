# Этап 2. Frontend-тестовая инфраструктура и smoke

Дата: 2026-11-11
Ветка: `refactor/stage-2-frontend-tests`
Основа: ТЗ «Рефакторинг CRM».

## Что сделано

- Добавлены Vitest, jsdom, Testing Library, MSW и тесты текущего shell: успешный вход, отказ во входе и разделы, доступные директору и клиенту.
- Добавлены Playwright и 10 браузерных smoke-сценариев на текущем UI: вход/выход, права ролей, навигация между разделами, создание компонента и шаблона, создание доски и карточки, drag-and-drop между колонками, раздел базы знаний, статья и загрузка вложения.
- Добавлен выделенный E2E-пользователь и тестовый сервер: backend слушает порт 3002, Vite — 4173; оба подключаются только к `servio_crm_test` на MariaDB 3308.
- Добавлены `npm run verify`, frontend unit-тесты и запуск изолированной тестовой БД в Windows. В CI добавлены MariaDB 11.7, подготовка тестовой базы и полный `verify`.
- ESLint-конфигурация покрывает TypeScript, правила Hooks и запрет explicit `any`. Существующие предупреждения legacy-кода оставлены как предупреждения.

Созданы: `eslint.config.js`, `vitest.config.ts`, `src/test/*`, `playwright.config.ts`, `e2e/*`, `backend/scripts/seed-e2e.mjs`, `scripts/ensure-test-db.mjs`, `scripts/start-e2e.mjs`, `scripts/verify.mjs`. Изменены корневые package-файлы, `vite.config.ts`, `.gitignore` и `.github/workflows/ci.yml`.

## Проверки

`npm run verify` — успешно на Windows:

- TypeScript frontend/backend — успешно.
- ESLint — 0 ошибок, 10 предупреждений на существующих участках legacy-кода.
- Prettier — все новые и затронутые инфраструктурные файлы соответствуют стилю.
- Frontend: 1 файл, 3 теста успешно.
- Backend: 8 файлов, 48 тестов успешно.
- Production-сборки frontend и backend — успешно.
- Playwright: 10 из 10 smoke-сценариев успешно.

Тестовая MariaDB использовала порт 3308 и базу `servio_crm_test`; приложение и тестовый сервер не обращались к рабочей БД на порту 3307. Новых миграций нет.

## Отклонения и границы

- Полный старый `npm run format:check` выявляет 58 ранее неформатированных файлов, включая существующие тесты. ТЗ запрещает править существующие тесты в инфраструктурном рефакторинге, поэтому `verify` проверяет Prettier для новых и изменённых инфраструктурных файлов. Массовое форматирование legacy-файлов не выполнялось.
- Текущий UI пока хранит выбранный раздел в React state и не имеет URL-маршрутов. Smoke проверяет существующие переходы между разделами; прямые ссылки относятся к этапу 5, когда появится маршрутизатор.
- Исходное расхождение типов двух колонок между миграцией и `schema.prisma` остаётся задокументированным в отчёте этапа 1; схема БД не менялась.

Существующие тесты не изменялись. Изменения не коммитились; PR не создавался.
