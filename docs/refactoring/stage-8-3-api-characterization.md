# Этап 8.3 — characterization API

## Объём проверки

В каталоге `backend/src/test/api.characterization.test.ts` перечислены 97 endpoint’ов. Общий набор для каждого защищённого маршрута проверяет запрос без авторизации (401) и фиксирует ответ с пустыми/default входными данными для каждой из четырёх ролей; для параметров пути подставляется отсутствующий числовой ID. Результат этой проверки — status snapshots, а не доказательство корректности успешного сценария.

Добавлены отдельные наборы по доменам в `backend/src/modules/*/*-api.characterization.test.ts`. Они проходят реальные HTTP-потоки и проверки отрицательных сценариев для request, board, knowledge, organization, store и Telegram API. Список успешных/ошибочных потоков описан прямо в тестах; тесты используют общие фабрики и очистку тестовой БД из `backend/src/test/api-test-app.ts`.

| Группа из endpoint-каталога | Без авторизации | Матрица ролей и default input | Явные HTTP-потоки этапа 8.3 |
|---|---|---|---|
| Health, auth | Не применимо для публичных маршрутов; защищённые проверяются общим набором | Статусы фиксируются общим набором | Не расширялись в этом этапе |
| Boards | 401 для защищённых endpoint’ов | Четыре роли; неизвестные ID/default input | CRUD доски, доступ, колонки, карточки, перемещение, архивирование/восстановление; ошибки валидации, отсутствующих сущностей и запрет CLIENT |
| Requests | 401 для защищённых endpoint’ов | Четыре роли; неизвестные ID/default input | Создание, список, обновление, комментарий, self-assign/unassign, удаление; ошибки валидации/неизвестного ID и запрет CLIENT |
| Knowledge | 401 для защищённых endpoint’ов | Четыре роли; неизвестные ID/default input | Разделы и статьи, вложения (загрузка/скачивание/удаление); неверный ввод, отсутствующие сущности и запрет CLIENT |

| Stores | 401 для защищённых endpoint’ов | Четыре роли; неизвестные ID/default input | CRUD, настройки доступа и проверка сохранения/чтения секретов; неверный ввод, отсутствующий ID и отказ по роли |
| Telegram | 401 для защищённых endpoint’ов | Четыре роли; неизвестные ID/default input | Интеграции, чаты, сообщения и привязки; неверный ID и запрет CLIENT |

## Зафиксированные ограничения и наблюдения

- Покрытие успешных сценариев пока не полное для всех 97 endpoint’ов. В частности, остаются без новых end-to-end HTTP-потоков health/auth и перечисленные в таблице группы; общую матрицу доступа нельзя считать заменой успешных сценариев.
- `POST /api/knowledge/import`, `GET /api/requests/procurement`, а также некоторые вторичные операции целевых доменов нужно сверить с перечнем вызовов в соответствующих тестах: их успешный контракт не заявляется как покрытый, если тест явно его не проверяет.
- Telegram `GET /api/telegram/chats/:id/messages` при нечисловом ID отвечает 500. Тест оставляет это поведение точным characterization-ожиданием; исправление ошибки не входит в этап, чтобы не менять наблюдаемое поведение без отдельного решения.
- При проверке кириллицы найдены и исправлены остаточные повреждения `С‚ип` и `С‚олько` в сообщениях knowledge/request API. Проверка `node scripts/check-text-encoding.mjs` проходит.
- Старый общий тест со status snapshots сохранён без структурных изменений, чтобы не нарушить доказанное прохождение на baseline. Доменные сценарии вынесены в отдельные тестовые файлы; перенос/разделение исходного snapshot-файла потребует отдельного сравнения snapshots с baseline.
