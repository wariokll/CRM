# Этап 8.3 — characterization API

## Объём

Каталог и матрица [97 API-маршрутов](stage-8-3-endpoint-matrix.md) покрывают отсутствие авторизации (для защищённых маршрутов — 401), status-снимки для четырёх ролей и прямые доменные HTTP-сценарии. Отдельные наборы лежат рядом с доменами в `backend/src/modules/*/*-api.characterization.test.ts`; оставшиеся маршруты и общий каталог проверяются тестами в `backend/src/test/` и существующими наборами доменов. Матрица указывает успешный поток, где он проверяется, и отрицательные сценарии для маршрута: невалидные body/query и отсутствующие сущности, когда применимо.

Role snapshots фиксируют фактические статусы для каждой роли; сами по себе они не доказывают успешный сценарий. Положительные потоки проверяются отдельными HTTP-тестами, на которые ссылается матрица.

## Зафиксированное поведение и ограничения

- `PUT /api/organizations/:id/members` для отсутствующей организации возвращает 500 из-за необработанного ограничения внешнего ключа. Поведение сохранено как наблюдаемое; исправление продукта в этот этап не включалось.
- `GET /api/telegram/chats/:id/messages` с нечисловым ID возвращает 500. Неизвестный числовой ID возвращает `200 []`; отсутствующий чат для update/relink/send возвращает 404.
- Неизвестный ID для self-unassign запроса возвращает 204.
- Неверные фильтры списка requests и assignees игнорируются (200); пустой комментарий и неверные периоды stats/procurement возвращают 400.
- Один Playwright smoke knowledge нестабилен: статья отображается в боковой панели, но после перезагрузки не появляется заголовком в основной области. В последнем полном прогоне этот сценарий упал; продуктовый код не менялся, поскольку этап фиксирует текущее поведение.

## Проверка

Последний `npm.cmd run verify`:

- текстовая кодировка, TypeScript, ESLint и Prettier прошли;
- frontend unit: 2 файла, 4 теста прошли;
- backend API: 37 файлов, 116 тестов прошли; coverage — statements 84.09%, branches 66.23%, functions 84.36%, lines 85.34%;
- frontend и backend production builds, SPA fallback smoke прошли;
- Playwright: последний полный прогон — 11 из 11. В предыдущем прогоне knowledge smoke не восстановил статью после перезагрузки; поведение было нестабильным и не исправлялось в рамках characterization.

API-характеризация этапа 8.3 выполнена: все 97 маршрутов отражены в матрице, добавленные и существующие API suites прошли в текущем backend прогоне. Полный `verify` выполнялся, но завершился с описанным падением knowledge UI smoke. Согласно правилам этапа найденное поведение оставлено без исправления и задокументировано. Последняя проверка неверного Telegram `linkedUserId` вошла в backend прогон; новые API suites ранее сверялись с baseline `D:\crm-original`.
